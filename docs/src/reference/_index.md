## API scope and imports

Use root imports such as `from larecs import World, Filter, SystemContext` for application code. The root export list in the [generated package index](../larecs) is checked against the initializer's actual imports during every build. Module-qualified names remain available in the generated module tree.

| Surface | Intended use |
| --- | --- |
| Application APIs | `World`, `Entity`, `Filter`, `Scheduler`, `System`, `SystemContext`, `KernelContext`, `EntitySelection`, `Resources` and the optional APIs linked above |
| Supported lower-level APIs | `HostStorage`, row accessors, `EntityRange`, `ResourceStorage`, component/resource traits and documented direct storage operations |
| Implementation utilities | Store allocation, component managers, device storage, lock managers, pools and transfer caches; these explain implementation mechanisms and are not the recommended application workflow |

Classification does not remove existing imports or compatibility commitments. A generated declaration's presence alone does not make it a recommended application entry point. Prefer systems and kernels for updates and scoped selections for structural batches; use direct storage for setup and individual operations.
