select_cluster

Section titled “select_cluster”

Source

Lock exactly the maintained cluster rows matching a component filter.

Exact declaration

Maintenance must be clean when membership is captured. Later writes do not change this selection’s membership; release it before maintenance. Multiple logical archetypes and dense-cluster blocks may contribute.

Parameters

  • filter: Filter[filter._include, filter._exclude, filter._is_exclusive, filter._read, filter._written] — Component filter intersected with the cluster membership.

Arguments

  • self: Self —
  • key: UInt64 — Exact registered classifier key.
  • selection: EntitySelection[world_origin, WorldTs] —

Returns

A locked selection, empty when the maintained cluster has no matches.

Raises

LarecsError: If partition storage is disabled, maintenance is pending, storage is locked, or no structural lock is available.

run

Section titled “run”

Source

Runs a kernel function for every entity matching its filter.

Exact declaration

Common call forms, for a kernel function move that takes a KernelContext:

  • context.run[move](): run on the host, sequentially.
  • context.run[move, threaded=True](): run on the host in concurrent chunks (experimental).
  • context.run[move, backend=ExecutionBackend.DEVICE](): run on an accelerator (experimental).
  • context.run[move](https://larecs.github.io/larecs/pr-preview/pr-247/larecs/system/SystemContext/read_capture(x/), mut_capture(y)): pass host-local values to a kernel that declares captures.

filter, required_resources, and capture_spec are inferred from the kernel’s KernelContext parameter. The tutorial Your first simulation shows a complete program.

Execution: The call returns after all kernel work has finished.

  • Host: KernelFunc is called once per non-empty physical store matching filter, one store after the other. Each KernelContext iterates that store’s rows; row indices are local to the context.
  • Threaded host: each matching store is split into chunks, and chunks may run concurrently on the world’s ThreadedExecutionConfig. With one worker or fewer matching rows than min_parallel_rows, the stores run sequentially.
  • Device: one launch covers all matching rows. Readable columns and resources are uploaded when the device copy is not current; write-only columns are not uploaded, so the kernel must set them for every row. Written columns, read-write resources, and mutable captures are copied back before run returns. DEVICE never falls back to HOST.

Access: include grants read-write component access, read read-only, and write set-only access; required_resources declares resource access the same way. Undeclared components and resources are rejected at compile time.

Empty matches: no kernel call happens. With DEVICE, the device storage and required resources are still validated, in that order, and a missing accelerator still raises.

This overload takes a thin kernel function. Use the overload taking kernel_func to run a closure that captures host-local values lexically; that one supports only sequential host execution.

Parameters

  • filter: Filter[filter._include, filter._exclude, filter._is_exclusive, filter._read, filter._written] — Components a row must have or lack, and how the kernel accesses them.
  • required_resources: Resources[required_resources.ResourceTypes, _readonly=required_resources._readonly, _writeonly=required_resources._writeonly] — Resources the kernel may access, and how.
  • capture_spec: Captures[capture_spec.Specs] — Ordered read-only and mutable host-local capture slots.
  • KernelFunc: def(KernelContext[filter, required_resources, capture_spec]) thin -> None — The kernel function, specialized for filter, required_resources, and capture_spec.
  • *Bindings: CaptureBindingType — The inferred types of the supplied capture bindings.
  • backend: ExecutionBackend — Execution target, HOST by default.
  • threaded: Bool — Run host chunks concurrently (experimental).

Arguments

  • self: Self —
  • *bindings: *Bindings.values — Read-only and mutable capture bindings, in the slot order of capture_spec.

Raises

Error: If the world is unusable or already executing; bindings or required resources are invalid; structural lock slots are exhausted; threaded row totals, job counts, or context sizes overflow; context preparation fails; or the device execution path fails to allocate or synchronize.

Constraints

threaded requires HOST and no capture bindings. DEVICE requires device-safe component and resource types.

Runs a kernel closure for every entity matching its filter.

Exact declaration

Common call form: context.run(move_by), where move_by is a nested function that takes a KernelContext and captures host-local values with a capture list such as {imm step}.

This overload runs sequentially on the host, exactly like the host path of the kernel-function overload: one call per non-empty matching physical store, returning after the last call. Captures may borrow host-local values with imm or mut; resource and component access work as in the kernel-function overload.

Parameters

  • filter: Filter[filter._include, filter._exclude, filter._is_exclusive, filter._read, filter._written] — Components a row must have or lack, and how the kernel accesses them.
  • required_resources: Resources[required_resources.ResourceTypes, _readonly=required_resources._readonly, _writeonly=required_resources._writeonly] — Resources the kernel may access, and how.
  • capture_spec: Captures[capture_spec.Specs] — Ordered read-only and mutable host-local capture slots.
  • KernelFunc: def(KernelContext[filter, required_resources, capture_spec]) -> None — The closure type, specialized for filter, required_resources, and capture_spec.
  • *Bindings: CaptureBindingType — The inferred types of the supplied capture bindings.
  • backend: ExecutionBackend — Must be HOST.
  • threaded: Bool — Must be False.

Arguments

  • self: Self —
  • kernel_func: KernelFunc — The closure to call once per matching physical store.
  • *bindings: *Bindings.values — Read-only and mutable capture bindings, in the slot order of capture_spec.

Raises

Error: If the world is unusable or already executing, a capture binding is invalid, or a required resource is missing.

Constraints

backend must be HOST and threaded must be False.
