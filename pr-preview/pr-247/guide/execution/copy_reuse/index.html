Reuse unchanged device copies

Skip uploading particle data that has not changed since the last device call. Use this after the kernel already passes the host and device comparison and a measurement shows that uploads matter. Reuse is off by default, set per world, and experimental. Written outputs still copy back to the host after every call.

Start with Execute on a device.

Enable reuse for a world

Section titled “Enable reuse for a world”

The stage uses the portable particle model and the unchanged movement kernel and system.

The kernel and system do not know about the transfer policy. You enable it on the world with World.reuse_device_copies, as the sequence below does before it moves walker six times:

Larecs keeps a revision for each resource and for each component column of a physical store, and advances it whenever the host may have changed that data. With reuse enabled, a device call uploads a resource or column only when the revision of its device copy, the bytes already on the device, differs from the current one. In the sequence:

  • read calls leave the revisions unchanged, so the second step reuses every input.
  • get through mutable storage advances the revision whether or not you write, so the step after get[Time]().delta = 0.5 uploads Time again.
  • A successful device call leaves the written Position current on both sides, so the next call can skip its upload too.

Retained capacity does not prove that its contents are current.

Larecs keeps device allocations between calls whether or not reuse is enabled; a kept allocation says nothing about whether its bytes are current. With reuse enabled, a read-only portable resource whose source is current skips prepare_device and reuses its view.

Invalidate a write Larecs cannot see

Section titled “Invalidate a write Larecs cannot see”

Larecs advances a revision when you call get, not when you later write through the reference it returned. The sequence keeps time_ptr across a run and then writes through it, so Larecs cannot see that write. scheduler.world.resources.invalidate_device[Time]() marks the device copy of Time stale, and the next call uploads it again. For writes through raw pointers to several resources or columns, World.invalidate_device_copies marks every device copy stale. Reacquiring a reference with get after each run avoids the problem.

Variations

Section titled “Variations”

Observe values without forcing an upload

Section titled “Observe values without forcing an upload”

Use read on storage and resources, or read-only queries, when you only look at values. They keep device copies current.

Turn reuse off

Section titled “Turn reuse off”

world.reuse_device_copies(False) discards the reuse records; the next device call uploads every input again. Calls stay synchronous either way.

Failures and limits

Section titled “Failures and limits”
Symptom Cause and fix
The device reads old values A write went through a reference kept from before a run, or a raw pointer. Reacquire references with get after each run, or invalidate the copy. Turn reuse off to confirm the diagnosis.
Inputs still upload on most calls Something advances their revisions: a mutable get, a host or threaded kernel that declares a write, a structural change, spatial maintenance, or a filter or selection that packs rows at a different offset. Use read for observation.
Written data still downloads Larecs copies written outputs back after every call; reuse skips only uploads.

The copy-reuse reference lists every operation that advances a revision.
