      Maintain particle locality

      Maintain particle locality

      Keep particles of the same grid cell next to each other in memory, and select exactly the particles of one cell. Use this when profiling shows that a pass reads nearby particles together and suffers from scattered rows. Grouping changes only where rows live; entity handles and component values stay the same. It does not find exact neighbors.

      Start with Update entities with systems and kernels and Create and remove entities in batches.

      Classify particles by grid cell

      The stage uses the portable particle model and an Int32 marker for particles that should not be grouped.

      @fieldwise_init
struct Position(Copyable, Movable, TrivialRegisterPassable):

    var x: Float32
    var y: Float32


@fieldwise_init
struct Velocity(Copyable, Movable, TrivialRegisterPassable):
    """Particle displacement per unit of simulated time."""

    var dx: Float32
    var dy: Float32


@fieldwise_init
struct Time(Copyable, Movable):
    """Shared simulated step length."""

    var delta: Float32

      A classifier computes a cluster key for each entity: a UInt64 that names its group. Entities with equal keys belong to the same cluster. This classifier uses one cluster per grid cell:

      comptime spatial_filter = Filter().read[Position]().exclude[Int32]()


@fieldwise_init
struct Grid(SpatialClassifier):
    """Classifies eligible particles by a bounded planar Morton cell."""

    comptime Accessor = EntityAccessor[spatial_filter]
    var cell_size: Float64

    def classify(self, entity: Self.Accessor) raises -> UInt64:
        """Reads only the declared position input.

        Args:
            entity: Borrowed classifier inputs; never retained.

        Raises:
            Error: If the cell width, coordinates, or cell bounds are invalid.

        Returns:
            The exact cell's Morton key.
        """
        ref position = entity.get[Position]()
        return morton_key_3d(
            grid_cell(Float64(position.x), self.cell_size),
            grid_cell(Float64(position.y), self.cell_size),
        )

      spatial_filter decides which entities Larecs classifies: those with a Position and no Int32 marker. Grid implements SpatialClassifier; its Accessor must use exactly that filter, with read-only access. grid_cell rounds a coordinate down to its cell, so -0.1 with cell width 1 lies in cell -1. morton_key_3d combines the cell coordinates into one key; the planar simulation leaves z at 0. Both raise for coordinates outside their documented bounds instead of clamping.

      Maintain placement after movement

      Movement and maintenance stay separate steps:

      comptime move_filter = Filter().include[Position]().read[Velocity]()
comptime move_resources = Resources().read[Time]()


def move(context: KernelContext[move_filter, move_resources]):
    """Moves each row using its velocity and the shared step length.

    Args:
        context: Matching rows and read-only time.
    """
    ref time = context.resources.get[Time]()
    for particle in context:
        ref position = particle.get[Position]()
        ref velocity = particle.get[Velocity]()
        position.x += velocity.dx * time.delta
        position.y += velocity.dy * time.delta
      @fieldwise_init
struct Move(System):
    """Moves particles and then refreshes their physical placement."""

    def update(mut self, mut context: SystemContext[...]) raises:
        """Runs explicit maintenance after movement completes.

        Args:
            context: Access to the unlocked world.

        Raises:
            Error: If execution or maintenance fails.
        """
        context.run[move]()
        context.world[].maintain_spatial()

      move declares Position writable, so Larecs marks every classified particle it visits as dirty: its key may be out of date. Positions change immediately, but rows move only when you call World.maintain_spatial. Then Larecs classifies each dirty particle once, using its final position, and moves rows to match the new keys. Kernels and systems never run maintenance by themselves.

      Maintenance moves rows, so the world must be unlocked. End every query and selection first, because empty queries and selections hold locks. Discard component references before maintenance, and look components up again by entity handle afterwards.

      Choose a placement policy

      Registering the classifier chooses how Larecs groups rows; it does not move rows by itself. The driver runs the same setup under both policies:

      def run_stage[partitioned: Bool]() raises:
    """Checks the same identities and values under both placement policies.

    Parameters:
        partitioned: Choose growable cluster stores instead of row ordering.

    Raises:
        Error: If classification, selection, movement, or checks fail.
    """
    var world = World[Position, Velocity, Int32]()
    world.resources.add(Time(1))
    var walker = world.storage.add_entity(Position(0.5, 0), Velocity(1, 0))
    var climber = world.storage.add_entity(Position(1.5, 0), Velocity(0, 2))
    var excluded = world.storage.add_entity(Position(-1, 0), Int32(1))
    world.register_spatial_classifier[spatial_filter](
        Grid(cell_size=1), partitioned=partitioned
    )
    world.maintain_spatial()
    assert_equal(world.storage.read[Position](walker).x, 0.5)
    assert_equal(world.storage.read[Position](excluded).x, -1)
      Policy Placement after maintenance
      partitioned=False (default) Larecs sorts the classified rows of each physical store by key, so equal keys become contiguous. The order of equal keys is unspecified.
      partitioned=True Each cluster of each logical archetype gets its own physical store, which starts with room for one row and doubles as it fills.

      Scroll horizontally to read the full figure.

      The same logical archetype supports two placement policies.

      Letters label entities, and colors and key labels mark clusters. All components and the entity ID of a row move together. In partition mode, a new particle, or one whose components changed, waits in a staging store: a physical store for rows that the next maintenance pass will place. Queries and kernels still visit staged rows.

      Select one cluster

      Partition mode can select exactly the particles with one key:

      comptime if partitioned:
    # New rows are visible to ordinary execution while still staged.
    var staged = world.storage.add_entity(Position(0.25, 0))
    assert_equal(len(world.storage.query[Filter().read[Position]()]()), 4)
    var context = SystemContext(world)
    with assert_raises():
        _ = context.select_cluster[Filter().read[Position]()](
            morton_key_3d(0, 0)
        )
    world.maintain_spatial()
    var clean_context = SystemContext(world)
    var selected = clean_context.select_cluster[Filter().read[Position]()](
        morton_key_3d(0, 0)
    )
    assert_equal(
        len(selected), 2
    )  # walker and staged; two logical archetypes
    selected.run[move]()  # only walker has Velocity
    assert_equal(len(selected), 2)  # membership stays fixed after the write
    selected^.release()
    world.maintain_spatial()
    assert_equal(world.storage.read[Position](walker).x, 1.5)
    assert_equal(world.storage.read[Position](staged).x, 0.25)

      SystemContext.select_cluster needs partition mode, a clean maintenance state, and an unlocked world; that is why the first attempt, made while staged waits in the staging store, raises. The selection contains walker and staged, which share key (0, 0) but belong to different logical archetypes; only walker has a Velocity and matches move. The membership stays fixed until you release the selection, even after walker moves to another cell. The selection matches the key exactly, not a radius, and adjacent keys need not be adjacent cells. For exact neighbors, check the actual distances in the cells you need, or build a separate spatial index.

      The driver checks the grid bounds and both policies:

      Variations

      Choose a maintenance cadence

      A pass with no dirty particles returns without touching rows. Otherwise it classifies only the dirty particles, but it still copies one key per entity slot, scans store metadata, and moves every row whose placement changes, with all of its components. Structural changes make the next pass reclassify every particle. Maintaining every few steps instead of every step trades placement accuracy for fewer row moves. Measure complete steps to choose, and compare the locality-sensitive pass on its own as well.

      Report writes that Larecs cannot see

      Larecs marks particles dirty when you write positions through set, a mutable get, or a kernel that declares the write. Use read or read-only queries to look at positions without marking them. After a write through a raw pointer, call world.storage.mark_spatial_dirty(entity) for each changed particle, or World.invalidate_spatial to reclassify everything.

      Move particles on a device

      Device movement marks the same particles dirty when it copies Position back. Maintenance and classification still run on the host afterwards.

      Failures and limits

      Failure Cause and fix
      maintain_spatial or select_cluster raises a locked-world error A query, selection, or storage range is still alive, possibly an empty one. End it first.
      Cluster selection requires clean spatial maintenance Particles are dirty or staged. Release old selections, call maintain_spatial, then select again.
      Cluster selection requires partitioned spatial storage Register the classifier with partitioned=True.
      grid_cell or morton_key_3d raises A coordinate is not finite, the cell width is not positive, or a cell lies outside the supported range. Change the cell width or the key encoding.
      maintain_spatial raises a classifier error Larecs keeps the previous rows, keys, and dirty marks. Fix the input and call it again.
      Particles stay in old clusters after raw writes Larecs could not see the write. Mark the particles dirty or invalidate, then maintain.

      The spatial reference lists classifier rules, key bounds, and the exact maintenance contract. The partition benchmark records measurements for one workload, not a general speed guarantee.

def run_stage[partitioned: Bool]() raises:
    """Checks the same identities and values under both placement policies.

    Parameters:
        partitioned: Choose growable cluster stores instead of row ordering.

    Raises:
        Error: If classification, selection, movement, or checks fail.
    """
    var world = World[Position, Velocity, Int32]()
    world.resources.add(Time(1))
    var walker = world.storage.add_entity(Position(0.5, 0), Velocity(1, 0))
    var climber = world.storage.add_entity(Position(1.5, 0), Velocity(0, 2))
    var excluded = world.storage.add_entity(Position(-1, 0), Int32(1))
    world.register_spatial_classifier[spatial_filter](
        Grid(cell_size=1), partitioned=partitioned
    )
    world.maintain_spatial()
    assert_equal(world.storage.read[Position](walker).x, 0.5)
    assert_equal(world.storage.read[Position](excluded).x, -1)

    comptime if partitioned:
        # New rows are visible to ordinary execution while still staged.
        var staged = world.storage.add_entity(Position(0.25, 0))
        assert_equal(len(world.storage.query[Filter().read[Position]()]()), 4)
        var context = SystemContext(world)
        with assert_raises():
            _ = context.select_cluster[Filter().read[Position]()](
                morton_key_3d(0, 0)
            )
        world.maintain_spatial()
        var clean_context = SystemContext(world)
        var selected = clean_context.select_cluster[Filter().read[Position]()](
            morton_key_3d(0, 0)
        )
        assert_equal(
            len(selected), 2
        )  # walker and staged; two logical archetypes
        selected.run[move]()  # only walker has Velocity
        assert_equal(len(selected), 2)  # membership stays fixed after the write
        selected^.release()
        world.maintain_spatial()
        assert_equal(world.storage.read[Position](walker).x, 1.5)
        assert_equal(world.storage.read[Position](staged).x, 0.25)

    var scheduler = Scheduler[Position, Velocity, Int32](world^)
    scheduler.add_system(Move())
    scheduler.run(steps=1)
    assert_equal(scheduler.world.storage.read[Position](climber).y, 2)
    assert_equal(
        scheduler.world.storage.read[Position](walker).x,
        Float32(2.5) if partitioned else Float32(1.5),
    )


def main() raises:
    """Checks grid bounds, default ordering, and partitioned selections.

    Raises:
        Error: If any spatial contract check fails.
    """
    assert_equal(grid_cell(-0.1, 1), -1)
    with assert_raises():
        _ = grid_cell(1048576, 1)
    with assert_raises():
        _ = morton_key_3d(0, -1048577)
    run_stage[False]()
    run_stage[True]()
    print("PASS: row ordering, partition staging, exact selections, and bounds")
