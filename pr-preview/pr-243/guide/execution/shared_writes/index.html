      Coordinate shared writes

      Coordinate shared writes

      Produce race-free shared results by writing per-particle output first and reducing it after run completes. Start with kernel access and read the execution restrictions before changing targets. Standalone synchronization primitives exist; automatic KernelContext.sync bindings and deferred retries do not.

      Write a separate output for each particle

      The stage uses the same particle types and shared time.

      @fieldwise_init
struct Position(Copyable, Movable, TrivialRegisterPassable):
    """Particle coordinates, using device-compatible scalar arithmetic."""

    var x: Float32
    var y: Float32


@fieldwise_init
struct Velocity(Copyable, Movable, TrivialRegisterPassable):
    """Particle displacement per unit of simulated time."""

    var dx: Float32
    var dy: Float32


@fieldwise_init
struct Time(Copyable, Movable):
    """Shared simulated step length."""

    var delta: Float32

      A resource or mutable capture would be one shared value for every worker. The additional Displacement below instead belongs to each entity.

      Write all output fields before a later step reads them.

      @fieldwise_init
struct Displacement(Copyable, Movable, TrivialRegisterPassable):
    """A private output for one particle, avoiding a shared kernel counter."""

    var x: Float32
    var y: Float32


comptime move_filter = Filter().include[Position]().read[Velocity]().write[
    Displacement
]()
comptime move_resources = Resources().read[Time]()


def move(context: KernelContext[move_filter, move_resources]):
    """Writes every per-row output before a later single-caller reduction.

    Args:
        context: Particle inputs and set-only displacement output.
    """
    ref time = context.resources.get[Time]()
    for particle in context:
        ref position = particle.get[Position]()
        ref velocity = particle.get[Velocity]()
        var dx = velocity.dx * time.delta
        var dy = velocity.dy * time.delta
        position.x += dx
        position.y += dy
        particle.set(Displacement(dx, dy))

      The filter grants read-write Position, read-only Velocity, and set-only Displacement. Every visited row initializes its output. The same row-local work can satisfy device/threaded restrictions without a shared increment.

      Reduce the completed output on the coordinating host caller.

      @fieldwise_init
struct Move(System):
    """Runs row work before a single-caller reduction."""

    def update(mut self, mut context: SystemContext[...]) raises:
        """Reduces completed per-row outputs without a shared kernel write.

        Args:
            context: Access to the world after synchronous kernel completion.

        Raises:
            Error: If execution or the reduction check fails.
        """
        context.run[move]()
        var total = Displacement(0, 0)
        for particle in context.world[].storage.query[
            Filter().read[Displacement]()
        ]():
            ref value = particle.get[Displacement]()
            total.x += value.x
            total.y += value.y
        assert_almost_equal(total.x, 9.25)
        assert_almost_equal(total.y, 18.5)

      The query starts after synchronous kernel completion. One caller sums all 37 outputs, obtaining (9.25, 18.5); there is no concurrent write to total. For a fully parallel reduction, use disjoint partial-output components and later passes with explicit dependencies. A single designated writer is also valid when it need not read unfinished work from other threads, as in the capture count example. A thread-zero branch alone is not a global barrier.

      Use standalone host primitives when you own the storage

      This independent check demonstrates atomic scalars and scoped guarded access outside ECS kernels.

      def check_primitives() raises:
    """Checks target-local host primitives independently of ECS bindings.

    Raises:
        Error: If an atomic or guard check fails.
    """
    var counter = AtomicValue[UInt32](0)
    var updates = counter.write_view()
    assert_equal(updates.fetch_add(1), UInt32(0))
    var result = updates.compare_exchange(1, 5)
    assert_true(result.exchanged)
    assert_equal(result.observed, UInt32(1))
    updates.store[Ordering.RELEASE](7)
    assert_equal(updates.load[Ordering.ACQUIRE](), UInt32(7))

    var state = Synchronized[UInt32](10)
    var access = state.write_view()
    var attempt = access.try_read()
    assert_true(attempt.is_acquired())
    var reader = attempt^.take()
    assert_equal(reader.value(), UInt32(10))
    assert_false(access.try_write().is_acquired())
    reader^.release()
    var write_attempt = access.try_write()
    assert_true(write_attempt.is_acquired())
    var writer = write_attempt^.take()
    writer.value() += 5
    writer^.release()
    var read_attempt = access.try_read()
    assert_true(read_attempt.is_acquired())
    var after = read_attempt^.take()
    assert_equal(after.value(), UInt32(15))

      AtomicValue owns a scalar; AtomicView borrows it. fetch_add returns the old value, and strong compare_exchange returns both success and the observed value. Only UInt32 and Int32 scalars are supported; add/subtract wrap at that width. Read views allow loads only.

      Synchronized owns guarded data; SyncView borrows its canonical protection state. Multiple read guards may coexist, while a writer excludes all guards. try_read/try_write make at most one compare-exchange attempt. Test is_acquired before consuming the result with take. A false result means Busy, including a changed state or reader saturation. It is not an automatic wait or a successful skipped update.

      References from guard.value() stay within the guard’s lifetime. Owners and guards are noncopyable; copied views share protection identity. Release by scope exit, including error unwinding, or by consuming guard^.release(). Errors do not roll back payload writes. There is no fairness, blocking wait, lock upgrade, or automatic retry: record required unfinished work for a later pass, or skip only if the application permits losing that update.

      Match ordering and backend support

      Public atomic operations default to relaxed ordering. Loads additionally accept acquire, stores release, and updates acquire, release, or acquire-release. Pass ordering at compile time. Relaxed counters do not publish adjacent ordinary data. Guards use acquire/release internally.

      Target Available behavior
      CPU, NVIDIA, AMD Full initial scalar/guard operation set, with CPU-wide or whole-device scope. Backend compilation does not establish hardware correctness.
      Apple device Relaxed/acquire loads, relaxed/release stores, relaxed add/subtract. Strong CAS, ordered add/subtract, and guards are explicitly rejected.

      Device primitives need aligned, initialized device-accessible payload/state that stays alive until completion. Low-level unsafe view constructors do not allocate, transfer, or validate that memory. A canonical unlocked state must protect every overlapping guarded payload. Host/device allocations are separate domains; these primitives do not permit concurrent CPU/GPU access to one allocation.

      Do not put an AtomicView or SyncView into an ordinary resource/capture and expect pointer transfer or automatic synchronization binding. Those raw-byte paths reject these views and aggregates containing them. Kernel binding adapters for these standalone owners remain unimplemented. A custom mutable resource adapter may implement a supported atomic protocol over its own target-local buffers; the checked scatter example demonstrates that separate contract.

      Run and troubleshoot

      The driver creates 37 movers, checks the reduction, and checks the standalone host operations.

      def main() raises:
    """Checks particle reduction and standalone host primitives.

    Raises:
        Error: If setup, execution, or a check fails.
    """
    var scheduler = Scheduler[Position, Velocity, Displacement]()
    scheduler.world.resources.add(Time(0.25))
    _ = scheduler.world.storage.add_entities(
        Position(0, 0), Velocity(1, 2), Displacement(0, 0), count=37
    )
    scheduler.add_system(Move())
    scheduler.run(steps=1)
    check_primitives()
    print(
        "PASS: per-particle outputs, single-caller reduction, and host"
        " primitives"
    )

      From the repository root, run pixi run mojo run -I src examples/particles/shared_outputs.mojo. Its PASS covers host reduction and primitives, not GPU synchronization. Use per-row or multi-pass output if a target lacks the operation you need; do not spin on Busy or invent a context.sync binding. Structural locks and resource leases protect invocation lifetimes and do not make shared writes race-free.
