      Execution
      Pass local values to kernels

      Pass local values to kernels

      Pass a step-local scale or result without storing it as a world resource. Start with movement and resources. Choose a lexical closure for sequential host borrows, or explicit slots for a thin kernel that can also run on a device. Threaded execution accepts neither capture path; its inputs belong in read-only resources or components.

      Borrow locals on the host

      Both independent programs on this page use these particle types.

      @fieldwise_init
struct Position(Copyable, Movable, TrivialRegisterPassable):
    """Particle coordinates, using device-compatible scalar arithmetic."""

    var x: Float32
    var y: Float32


@fieldwise_init
struct Velocity(Copyable, Movable, TrivialRegisterPassable):
    """Particle displacement per unit of simulated time."""

    var dx: Float32
    var dy: Float32


@fieldwise_init
struct Time(Copyable, Movable):
    """Shared simulated step length."""

    var delta: Float32

      The names match the core simulation. The explicit-capture variant uses the same Float32 representation for device-compatible arithmetic; see device eligibility.

      The lexical stage defines move inside Move.update and passes it as a value.

      @fieldwise_init
struct Move(System):
    """Counts particles through a sequential host closure."""

    def update(mut self, mut context: SystemContext[...]) raises:
        """Moves the particles and observes a synchronous captured result.

        Args:
            context: Access to the particle world.

        Raises:
            Error: If resources, execution, or the visit check fail.
        """
        var scale: Float32 = 2
        var visits = 0

        def move(
            rows: KernelContext[
                Filter().include[Position]().read[Velocity](),
                Resources().read[Time](),
            ]
        ) {imm scale, mut visits}:
            """Moves each row and counts it through a host borrow.

            Args:
                rows: One matching physical store's rows and time.
            """
            ref time = rows.resources.get[Time]()
            for particle in rows:
                ref position = particle.get[Position]()
                ref velocity = particle.get[Velocity]()
                position.x += velocity.dx * time.delta * scale
                position.y += velocity.dy * time.delta * scale
                visits += 1

        context.run(move)
        assert_equal(visits, 2)

      imm scale borrows the local input and mut visits borrows the counter. context.run(move) selects the value-taking overload, which supports only sequential HOST. Every matching physical store receives a call, so visits increments inside the row loop. Completion is synchronous; its final value is visible at the assertion. Do not capture an alias that structurally changes the world while rows are borrowed.

      The driver checks two matching physical stores with different compositions.

      def main() raises:
    """Checks the closure across two matching physical stores.

    Raises:
        Error: If setup, execution, or a position check fails.
    """
    var world = World[Position, Velocity, Int32]()
    world.resources.add(Time(0.25))
    var walker = world.storage.add_entity(Position(0, 0), Velocity(1, 0))
    var climber = world.storage.add_entity(
        Position(5, 0), Velocity(0, 2), Int32(1)
    )
    var scheduler = Scheduler[Position, Velocity, Int32](world^)
    scheduler.add_system(Move())
    scheduler.run(steps=1)
    assert_almost_equal(scheduler.world.storage.read[Position](walker).x, 0.5)
    assert_almost_equal(scheduler.world.storage.read[Position](climber).y, 1.0)
    print("PASS: lexical host captures across two stores")

      walker and climber both move once, and the counter counts rows across both calls. The extra Int32 component puts climber in another logical archetype; it does not change the movement filter. Run pixi run mojo run -I src examples/particles/lexical_closure.mojo from the repository root to check the stage.

      Declare explicit slots for a thin kernel

      The alternative stage declares ordered Captures slots, independent of the world’s resource types.

      comptime move_filter = Filter().include[Position]().read[Velocity]()
comptime move_resources = Resources().read[Time]()
comptime locals_spec = Captures[ReadCapture[Float32], MutCapture[Int32]]()


def move(context: KernelContext[move_filter, move_resources, locals_spec]):
    """Moves particles and records the processed count with a single writer.

    Args:
        context: Rows, time, and ordered scale/count capture slots.
    """
    ref time = context.resources.get[Time]()
    var scale = context.captures.get[0]()
    for particle in context:
        ref position = particle.get[Position]()
        ref velocity = particle.get[Velocity]()
        position.x += velocity.dx * time.delta * scale
        position.y += velocity.dy * time.delta * scale
    # The count is shared, not one private scalar per device thread.
    comptime if is_gpu():
        if global_idx.x != 0:
            return
    context.captures.get[1]() += context.length

      Slot 0 is a ReadCapture input; slot 1 is a MutCapture result. get[0] is immutable. The output is shared by all invocations/threads, not private per row. On host, one writer per store adds that store’s length. On device, only global thread zero adds the packed length, after its own row loop. This works because the result does not read other threads’ outputs. It is not a barrier or a general parallel reduction.

      Bind locals in exactly the declared order when the system runs.

      @fieldwise_init
struct Move[backend: ExecutionBackend](System):
    """Binds local values for one synchronous step."""

    def update(mut self, mut context: SystemContext[...]) raises:
        """Checks count copy-back before the system returns.

        Args:
            context: Access to the simulation world.

        Raises:
            Error: If binding, execution, or the count check fails.
        """
        var scale: Float32 = 2
        var processed: Int32 = 0
        context.run[move, backend=Self.backend](
            read_capture(scale), mut_capture(processed)
        )
        assert_equal(scale, 2)
        assert_equal(processed, 37)

      read_capture and mut_capture borrow their locals until run finishes. Host execution borrows the original values; device execution uploads each binding on every call and copies mutable slots back before return. Empty matches leave captures unchanged. The checked full program also tests an empty world and 37 particles split across two physical stores.

      From the repository root, execute this independent stage:

      pixi run mojo run -I src examples/particles/captures.mojo

      The program always checks host execution. Its explicit device PASS line means actual execution and copy-back; a SKIP line means that device validation did not run. Device setup explains availability failures.

      Restrictions and recovery

      Failure or restriction Response
      Wrong slot count, type, or mutability Match Captures in binding order. Slots may share a type; their index still distinguishes them.
      Conflicting borrows of one local Use separate values; the borrow checker rejects overlapping read/mutable bindings.
      Heap owner or host pointer in a device capture Captures transfer trivial bytes, not object graphs, and perform no DevicePassable conversion. Use a portable resource for owned storage.
      A captured reference outlives execution Keep references and pointers inside the invocation. Neither lexical nor explicit capture references may escape it.
      Several writers update one output Choose a proven single writer or per-row output and a later reduction. Mutable capture access supplies no synchronization.

      Device execution remains experimental. Prefer explicit bindings when the same thin kernel must run on both targets; use portable resources when the input persists between steps or owns data.

def run_stage[backend: ExecutionBackend]() raises:
    """Checks empty bindings, two physical stores, and a partial device block.

    Parameters:
        backend: Target to validate.

    Raises:
        Error: If setup, execution, or an assertion fails.
    """
    var world = World[Position, Velocity, Int32]()
    world.resources.add(Time(0.25))
    var scale: Float32 = 2
    var processed: Int32 = 9
    var empty_context = SystemContext(world)
    empty_context.run[move, backend=backend](
        read_capture(scale), mut_capture(processed)
    )
    assert_equal(processed, 9)
    _ = world.storage.add_entities(Position(0, 0), Velocity(1, 2), count=18)
    _ = world.storage.add_entities(
        Position(0, 0), Velocity(1, 2), Int32(1), count=19
    )
    var scheduler = Scheduler[Position, Velocity, Int32](world^)
    scheduler.add_system(Move[backend]())
    scheduler.run(steps=1)
    for particle in scheduler.world.storage.query[move_filter]():
        assert_almost_equal(particle.get[Position]().x, 0.5)
        assert_almost_equal(particle.get[Position]().y, 1.0)


def main() raises:
    """Always executes host checks and labels accelerator coverage explicitly.

    Raises:
        Error: If any executed target fails.
    """
    run_stage[ExecutionBackend.HOST]()
    print("PASS: explicit host captures, including empty matches")
    comptime if has_accelerator():
        run_stage[ExecutionBackend.DEVICE]()
        print("PASS: actual device captures and synchronous count copy-back")
    else:
        print("SKIP: device captures (no accelerator compilation support)")
